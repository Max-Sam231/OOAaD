# ООАиП: что сделать к занятию

К занятию нужен сервер, который реально запускается: принимает команды по WebSocket и выполняет их в игре с собственным scope. Плюс демо нового правила (топливо) без правки старого кода.

## Где мы сейчас

Лабы первого семестра на `main` закрыты, 100 тестов зелёные. Но это только библиотека команд: запускаемого сервера нет.

- **На main:** ЛР2 целиком (Move, Rotate, Macro, Send, Actions.Start/Stop, CI ≥ 90 %), ЛР3 (репозиторий объектов, выстрел, торпеда, `Game`, авторизация), ЛР4 частично (`CheckCollisionCommand` + матрица).
- **Не влито:** `feature/5lab` — кодогенерация адаптеров; `feature/4lab_3` — коллизии по секторам; `feature/IsCollision` и `feature/collision-data-processor` — квадрантный детектор.
- **Чего нет совсем:** endpoint, приём сообщений, scope на игру, описание игры текстом, правила из event storming (топливо, ракеты, итоги).

## Задачи

Задачи 1, 2 и 6 независимы, их можно брать сразу. 3 → 4 → 5 идут по порядку: каждая опирается на предыдущую. Каждая задача — Issue + ветка + PR, покрытие ≥ 90 %.

## Сценарий показа

Показываем путь одной команды от клиента до изменения состояния и одно новое правило, добавленное без правки кода.

1. Запустить сервер (`dotnet run`), создать две игры: с топливом и без.
2. Подключить тестового клиента по WebSocket, отправить «начать движение» кораблю в каждой игре.
3. Показать приходящие состояния: в игре с топливом корабль останавливается, когда топливо кончилось.
4. Открыть diff демо-задачи: только новые файлы (команды, интерфейс, регистрации), существующие классы не тронуты.
5. Показать CI с покрытием и историю коммитов.
6. Рассказать дальнейший план: многопоточность с планировщиком, сериализация и перенос игры между серверами, горячее обновление scope'ов.

Каждый должен уметь объяснить свою часть кода: преподаватель спрашивает, как это работает.

## Правила

Код от ИИ допускается, но если он не следует этой архитектуре, преподаватель его не примет (ПЗ3).

- Любое действие — `ICommand`; объекты создаются только через `Ioc.Resolve`, без `new` в прикладном коде.
- Новое поведение — новые файлы и регистрации, старые классы не переписываем.
- Составное поведение — макрокоманды из `Specs.*`, не наследование.
- Сначала одна игра и монолит; многопоточность и несколько серверов — потом.
- Коммитить часто и понемногу: по истории должно быть видно, что работа шла постепенно, а не за ночь до сдачи.
- Срок: зачёт в конце декабря, около двух месяцев.
